# IGRB: reproducible back-order forecasting experiments

Executable code, raw predictions, trained models, statistical summaries and manuscript source for intermittency-aware graph residual boosting (IGRB), relation-aware baselines and emergency-replenishment evaluation.

## Reproduce the final IGRB study

```bash
python -m hetst.experiment_igrb --output results/igrb_final
python -m hetst.experiment_igrb_generalization --output results/igrb_gen_s --cases seasonal
python -m hetst.experiment_igrb_generalization --output results/igrb_gen_i --cases intermittent
python -m hetst.experiment_igrb_generalization --output results/igrb_gen_c --cases correlated
python -m hetst.experiment_igrb --output results/igrb_errorweighted --cases seasonal,correlated --shifts none --skip-policy --error-weighting
python -m hetst.experiment_igrb --output results/igrb_noadi --cases intermittent,retail --shifts none --skip-policy --no-adi
python -m hetst.analyze_igrb
python -m hetst.analyze_adi_sensitivity
python -m hetst.analyze_fmcg
cd paper
python make_igrb_figure.py
python make_manuscript_figures.py
pdflatex -interaction=nonstopmode -halt-on-error igrb_main.tex
pdflatex -interaction=nonstopmode -halt-on-error igrb_main.tex
```

**Evidence status:** this package does not reproduce the old manuscript's numbers. The original published code archive was recovered and audited; confirmed physical-conservation and temporal-calibration defects required a new benchmark and new executions. The old results are never imported by the training or analysis code. Read `RECOVERED_CODE_AUDIT.md` and `PROTOCOL.md` first.

## Install

Python 3.12 was used. Use a clean virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

For a CPU-only PyTorch build, install the pinned torch version from https://download.pytorch.org/whl/cpu before installing the remaining requirements. GPU acceleration is optional, but the reported execution was single-thread CPU per process; the supplied runner uses CPU tensors deliberately.

## Data

UCI Online Retail (Daqing Chen, 2015), DOI https://doi.org/10.24432/C5BW33, CC BY 4.0. Download the original ZIP from https://archive.ics.uci.edu/static/public/352/online+retail.zip and place it outside version control. Then:

```bash
python -c "from hetst.data import retail_demands; retail_demands('/absolute/path/online_retail.zip','data')"
```

The source has sales transactions, not observed inventory states or back-orders. Twelve SKUs are chosen by training-period volume and each sales series is scaled using its training mean into synthetic interchangeable demand units. The derived demand matrix and exact selection metadata are supplied for reproducibility. Do not describe its artificial 16-node graph as an observed retail network.

The optional FMCG-inspired robustness check uses the public **simulated** FMCG Daily Sales Data (2022--2024), not a confidential or observed industrial panel. Place `FMCG_2022_2024.csv` outside version control and run:

```bash
python -c "from hetst.data import fmcg_demands; fmcg_demands('/absolute/path/FMCG_2022_2024.csv','data')"
python -m hetst.experiment_igrb --output results/igrb_fmcg --cases fmcg
python -m hetst.experiment --output results/fmcg_baselines --cases fmcg --methods Persistence,LocalBalance,XGBoost --shifts none --skip-policy
python -m hetst.analyze_fmcg
```

The adapter clips three negative sales entries to zero, chooses twelve SKUs and computes scaling from the first 60% of days only. The panel supplies demand shapes; topology, inventory states, disruptions and back-order labels remain simulated. It is therefore a robustness check, not industrial external validation.

The other three demand cases are generated by `hetst/simulator.py`; they are stress regimes, not independent real-world datasets. No proprietary data are used. M5 and DataCo results from the old manuscript are not retained because there is no verified run evidence for them here.

## Reproduce all executed main runs

```bash
python -m hetst.experiment --output results/seasonal --cases seasonal --epochs 40
python -m hetst.experiment --output results/intermittent --cases intermittent --epochs 40
python -m hetst.experiment --output results/correlated --cases correlated --epochs 40
python -m hetst.experiment --output results/retail --cases retail --epochs 40
python -m hetst.experiment --output results/ablation --cases retail --methods NoTime,NoEdge,SingleHead,NoSelf,ClsOnly,RegOnly --epochs 40 --shifts none --skip-policy
python -m hetst.analyze
```

Commands may run independently with separate output directories. The default five model seeds and all configuration grids are in `PROTOCOL.md`. Existing `complete.json` files allow resuming a stopped command; for a truly new run or any changed configuration use a new output directory. Do not reuse a completed output directory after changing model/data settings.

Each run includes the selected neural checkpoint (`model.pt`) or XGBoost models, validation history, forecast probabilities/magnitudes/labels/time indices, and one ledger per closed-loop policy scenario. Main `metrics.csv` and `policy.csv` are incremental. `data.npz`, `split.json` and `normalization.json` identify the evaluated data and splits. Shared data seeds isolate model-optimization variability; five model seeds do not equal five independent data sets.

## Meaning of method labels

- `HetST`: three-layer, relation-aware multihead attention with sinusoidal and cyclic context, separate self transformation, class-weighted occurrence loss and positive-only severity loss.
- `RelGRU`: the same relational attention encoder applied at each of six time steps, followed by a GRU. This is an important stronger temporal comparator.
- `HomGAT`: relation-shared attention. The relation indicator is retained as an edge feature; the ablation removes relation-specific weights, not all relation information.
- `RGCN` / `GCN`: relational / homogeneous mean-aggregation comparison architectures, not claims of exact reproduction of every detail of the original R-GCN/GCN papers.
- `TGRU`: homogeneous mean graph encoder plus GRU; **not labeled DCRNN**.
- `LSTM`: a shared-weight per-node LSTM, not separate independently trained LSTMs for every node.
- `LocalBalance`: Gaussian local balance score using current inventory/backlog and training demand moments, not an optimal echelon-base-stock policy.
- `XGBoost`, `Persistence`: causal local-history tree and state-persistence comparisons.
- `ClsOnly` / `RegOnly`: separately optimized single-task models. An untrained output head is excluded from evaluation.

## Decision evaluation

Models are trained on the fixed order-up-to system, then frozen. Forecasts determine emergency purchases with two-cycle arrival delay and a shared capacity bound. New inventory states feed back into subsequent forecasts. Every method sees the same demand and disruption realization; all purchases are included in costs. No policy is tuned against test costs. This is a fixed heuristic deployment rule, not decision-focused training or a guarantee of optimal control.

## Rebuild the article

```bash
python -m hetst.analyze_igrb
python -m hetst.analyze_adi_sensitivity
cd paper
pdflatex -interaction=nonstopmode -halt-on-error igrb_main.tex
pdflatex -interaction=nonstopmode -halt-on-error igrb_main.tex
```

References are embedded in `igrb_main.tex`, so no `.bbl` or BibTeX invocation is needed. Figures and generated tables reside in the same directory. The separate article ZIP contains only required submission source and the compiled manuscript.
`igrb_tables.tex` is the frozen manuscript-facing table snapshot. Its numeric inputs are regenerated as CSV files by the analysis commands above; it is not silently rewritten during compilation.

## Scope and publication

These experiments are small-network controlled evidence. No result is presented as observed FMCG validation or universal superiority. The archived code, derived data and result files are available at https://doi.org/10.5281/zenodo.22982026.
